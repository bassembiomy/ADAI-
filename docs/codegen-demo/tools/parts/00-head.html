Reading the code generator — source line → emitted C line

This is the code-generation process as implemented, read out of the generator itself. Each generator excerpt below is sliced from the repository at build time; each emitted-C excerpt is the verbatim output of that same code for the demo model. Nothing here was rewritten by hand, and the document cannot drift from the source unless the build itself is re-run: python3 docs/codegen-demo/tools/build_source_doc.py.

The whole generator in one sentence. smCGenerator.ts is a set of pure render functions (renderConfigHeader, renderMappingSource, renderCoreSource, renderSafetySource, renderUserLogicSource, renderMcalHeader, …), each of which walks one slice of the semantic IR and returns a string; generateCArtifacts() calls them, adds the generated test/manifest package, and returns a file list.

The three techniques it uses, and nothing else.

  1. Ordering + indexing — orderedStates()/orderedLayers()/buildIndex() turn model IDs into small integers once; every other function then refers to a state as SM_ST_X and to a state's function as SM_Enter_Deep_7.
  2. One render function per C construct — renderActions(), renderMarkEntered(), renderRouteEnabled(), renderEnterStateAlongPath(), renderRestoreStateBody(), renderCommitRoute(), renderTransitionPhase(), renderExecuteFunctions(), renderExitFunctions(). Each takes IR objects plus an indent string and returns source text.
  3. Emit when the IR says so — a construct exists in the C output iff a condition on the IR is true: state.childLayerIds.length > 0, state.activeSlot >= 0, layer.activeSlot !== null, route.destinationKind === 'history', ir.activeSlotCount > 0, ir.ioMappings.length > 0, ir.verification.cStandard === 'c90'. This is why a small model produces a small file.

Why the generated C is deterministic. Every iteration order is defined by an explicit sort (activityIndex, activeSlot, priority, localeCompare), every name comes from toCIdentifier(), and no render function reads the clock, the environment or a random source — the emitted bytes are a function of the IR alone.

Demo model (committed at docs/codegen-demo/thermal-model.ts, generated artefacts in docs/codegen-demo/evidence/): 10 states, 5 layers — one OR root, one OR container child layer owning a deep-history junction, one AND parallel layer, and two OR layers inside the parallel regions. Regenerate with npx tsx docs/codegen-demo/generate.ts; the run also replays the model on the compiled C: 29/29 interpreter frames ≡ 29/29 compiled-C frames.
