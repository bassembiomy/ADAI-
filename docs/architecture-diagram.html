🔄 Canonical data flow (top → bottom, then loop back)

  1. Edit: workspaces mutate the project model in App.tsx (blocks · parts · ports · connectors · relationships · states · labs).
  2. Guard: sysmlIntegrityService + reportModelConsistency cascade/clean deletions; persistence writes snapshots / .adia.
  3. Report: features/reporting builds a validated rev_* snapshot → renders BDD/Req/IBD/Trace/SM/XHMI → exports PDF/DOCX.
  4. Execute: domain engines run headless (VLab DAE, X-Bridges blocks, SM→C, OPM→C, DOE/GMDH) — each with its own Vitest goldens.
  5. Deploy & observe: HIL orchestrator builds (hash-pinned toolchain) → policy-gated flash → serial telemetry back into dashboards.

⚠️ Known decoupling (read before extending)

  1. SysML ⇆ simulation is manual: no automatic Block→VLab/X-Bridges binding; verify/allocation links are labels, not execution bindings.
  2. Two deletion paths coexist: UI cascade helper vs pure-rule integrity service — converge new logic on the service.
  3. Report assembly: prefer the canonical features/reporting snapshot pipeline over legacy inline filters in App.tsx.
  4. HIL is deny-by-default: build/flash/probe go through src/security/hil* policy gates; keep recipes + hashes in sync.
