1The idea: state becomes data, behaviour becomes code

A hierarchical state machine is a graph plus a small runtime. Code generation is the act of specialising that runtime for one graph, so that at run time nothing about the graph has to be interpreted: every lookup is an index, every choice is a switch, every set of states that must be entered or exited is already an explicit list in the generated source.

The generator is therefore not a template that prints the picture back as code. It is a total, deterministic function from a validated semantic IR to a fixed file set:

model (JSON, V5)  --migrate-->  legacy-free model  --buildSemanticModel-->  SemanticModel (IR)
                                                                                  |
                                        generateCArtifacts(ir, options)  <---------+
                                                  |
        +-----------------------------------------+-----------------------------------------+
        |                    |                    |                    |                   |
   sm_config.h         sm_core.{h,c}       sm_mapping.{h,c}      sm_safety.{h,c}     sm_user_logic.{h,c}
   (types, limits)     (execution engine)  (index tables)        (fault containment) (your actions)
                                                  |
                                        plus mcal_dio.h, 9 generated test suites, evidence, reports

Five mechanisms carry the whole transformation. Everything in the generated C is one of them:

1 · Symbols

Every state, layer and slot becomes a #define plus an enum member with a stable numeric identity. Model UUIDs never appear in the output — the C compiler sees only small integers.

2 · Shape

Hierarchy becomes two constant tables (parent layer, parent state) and one active-slot map. "Is warming active?" stops being a search and becomes state_active[SM_ST_WARMING_IDX].

3 · Control

Each state and layer gets Enter_*, Restore_*, Execute_*, Exit_* functions. Mutual recursion mirrors the containment tree, so nesting is expressed by the C call graph itself.

4 · Commitment

Exit sets and entry paths of every transition are computed at generation time and emitted as straight-line code: no run-time graph walk, no allocation, no recursion discovery.

5 · Defence

Safety is emitted as constant metadata (SM_Layer_Has_Children_Map, SM_Is_Direct_Layer_Child) plus a bounded consistency check that runs before and after every tick.

… and the seam

Only sm_user_logic.c contains model-authored action code; regeneration never touches it, and the engine never inlines user logic into its own switches.

Consequence: the generated program is a state machine interpreter with the graph compiled in

The runtime footprint per instance is O(states + layers) bools and uint32s, and the tick cost is O(active states + outgoing transitions of those states) — the same asymptotics as a hand-written Stateflow-style machine, with the added property that nobody wrote the 1 069 lines of sm_core.c by hand.

2The seven-stage pipeline, and what each stage guarantees

The generator is defensive about its input exactly as much as about its output. Each stage is a gate: an error at stage n makes everything downstream inexpressible rather than wrong.

Stage 0 — Author model (src/types/sm_types.ts, smModel.ts, smFixtures.ts)

States with parentId, entry/during/exit scripts, priority, autostart, safe/terminal flags; transitions with condition | afterTicks | type; variables with types and initial literals; layers declaring OR/AND decomposition; junctions typed junction | history | deep-history. Geometry (x/y/width) exists only for the editor.

▼raw, possibly legacy-shaped model

Stage 1 — Migration (smModelMigration.ts)

Schema V4 → V5, default verification policy, legacy history metadata repair, normalisation of parallel flags. Guarantee: downstream code sees one shape only. In this run: 0 diagnostics.

▼typed model

Stage 2 — Semantic build (smSemanticBuilder.ts → SemanticModel)

This is where model concepts become engineering concepts, and it is the most consequential stage. It computes:

  • enumName / activityIndex — deterministic C identity per state (sorted, not insertion order).
  • activeSlot — one RAM slot per non-empty OR layer; -1 for parallel containers that are only tracked by state_active[].
  • exitStateIds / entryStateIds per transition — from LCA computation, including cascade exits of descendants.
  • routes[] — the path a transition actually takes, with destinationKind: 'state' | 'history'; junction chains are flattened into a single route so the emitted code has no decision loop.
  • guard / actions AST — parsed expressions (smExpressions.ts) instead of raw text, so the C emitter can type-guard casts and reject what it cannot render.

Guarantee: the C emitter never has to interpret the model's text; it reads a fully resolved structure.

▼semantic IR

Stage 3 — Validation (smSemanticValidator.ts) and analysis (smAnalysisEngine.ts)

Reachability, autostart existence, unambiguous history ownership, slot/total consistency, OR/AND well-formedness. Analysis produces requirements-to-state traceability and static reachability used by the reports. Guarantee: if this stage reports an error, no C is emitted at all (see scripts/verify_sm_codegen.ts, which returns 1).

▼validated IR + analysis

Stage 4 — C emission (smCGenerator.ts, 1 963 lines including templates; expressions in smCExpressions.ts)

One pure function per artifact. Rendering is string-concatenation over ordered collections, which is why output is byte-stable for a given IR (smCGenerator.golden.test.ts snapshot).

▼package: production/ + tests/ + verification/

Stage 5 — Self-check on its own output (verifyGeneratedCStructure)

The generator re-reads the C it just produced and asserts that every instance->data.<member> access corresponds to a declared member of SM_Data_t; failures become GEN_C_UNDECLARED_DATA_MEMBER errors. This is a cheap, high-yield guard for a string-based emitter.

▼structurally self-consistent package

Stage 6 — Conformance pipeline (smPipelineOrchestrator.ts, 12 activities)

Host compile with strict flags → run generated tests → ASan/UBSan → gcov coverage → differential C-vs-interpreter → static analysis → MISRA → cross-compile for the target → hardware (always PENDING until a bench exists). Acceptance is fail-closed: deriveAcceptance() rejects the bundle unless every required activity is PASS or NOT_APPLICABLE (see §7).

4.1 What is modelled

root                         (OR)

 │   ├─ standby autostart
 │   └─ warming  entry/exit, AND container
 │       ├─ pwm_bank   ├─ pwm_low (autostart) ├─ pwm_high
 │       └─ fan_bank   ├─ fan_low (autostart) ├─ fan_high

  begin_warmup   standby → warming        guard: start_cmd      action: heat_cycles = 0
  pwm_step_up    pwm_low → pwm_high       trigger: after 20 ticks (200 ms)

4.3 The three computed structures that make generation local

activityIndex → C identity

States are ordered once (by activity index) and receive 1..N. The number is not a hash of the UUID: it is an array index, so state_active[], state_timers[], deep_history[][] and both mapping tables all agree by construction. In this model warming = 3, pwm_high = 6.

activeSlot → where the "current child" lives

Only OR layers hold a slot: root=0, heater_children=1, pwm_children=2, fan_children=3. The AND layer warming_regions gets none and states pwm_bank/fan_bank get -1, because parallel regions are always active together and are tracked by state_active[]. An empty OR layer would consume no slot at all (REQ-GEN-SAF-002).

routes → no junction at run time

For resume_heater the IR records destinationKind: 'history' with destinationJunctionId, plus entryStateIds = [heater]: the emitter knows to enter the owner, then ask the history bit matrix which child to restore. Nothing about that decision survives as a data structure in the C.

The tick window is derived from tickMs and tickToleranceMs by one rule: MIN = tick − tolerance, MAX = tick + tolerance. A platform whose timer is coarser than the tolerance cannot use the generated machine — that is checked in SM_Step, not silently tolerated.

5.4 Dispatch is a switch, not a table of function pointers

static bool SM_Execute_Layer_0(ADIA_Instance_t *instance)
{
    switch (instance->active_states[0U]) {
        case SM_ST_HEATER:
            return SM_Execute_State_1(instance);
        case SM_ST_OVERHEAT:
            return SM_Execute_State_10(instance);
        default: return false;
    }
}

The root layer dispatches to two states. There is no indirect call: the compiler can inline, can prove which functions are reachable, and the linker can drop the rest (relevant for the -Os numbers in §9). Compare with a naive interpreter loop for (t of transitions) if (eval(t.guard)) …: same semantics here, but the generated version cannot be defeated by a malformed transition table at run time.

    for (slot_index = 0U; slot_index < SM_NUM_ACTIVE_SLOTS; ++slot_index) {
        instance->active_states[slot_index] = SM_NODE_INVALID;
        instance->history_states[slot_index] = SM_NODE_INVALID;
    }
    for (layer_index = 0U; layer_index < SM_NUM_LAYERS; ++layer_index) {
        for (state_index = 0U; state_index <= SM_NUM_STATES; ++state_index) {
            instance->deep_history[layer_index][state_index] = false;
        }
    }
    for (state_index = 0U; state_index <= SM_NUM_STATES; ++state_index) {
        instance->state_active[state_index] = false;
        instance->state_timers[state_index] = 0U;
    }
    instance->error_status = SM_ERR_NONE;
    instance->fault_latched = false;
    instance->error_status = SM_Validate_Mapping_Configuration();
    if (instance->error_status != SM_ERR_NONE) {
        return SM_ERR_CONFIGURATION;
    }
    SM_Enter_Layer_Default_0(instance);
    return SM_ERR_NONE;
}

The first statement after the null guard is memset, and everything semantic follows: variables, slot arrays, bit matrices, error status, then the compiled-in mapping check, and only then the root layer's default entry. Two design points are visible in the emitted code:

  • Self-referential functions are kept alive on purpose via (void)SM_Enter_Deep_1; style statements. SM_Restore_State_k and SM_Exit_Layer_No_History_k can only be reached through history or non-recording paths, and the generator does not want -Wunused-function (or a linker) to remove them.
  • Tracing is not allowed to leak into initialisation. With SM_TRACE_ENABLED, trace_sink is explicitly cleared before any entry action runs, so a caller-supplied garbage pointer cannot be called; the documented lifecycle is SM_Init() then SM_SetTraceSink() (Correction 3 in docs/STATE_MACHINE_CODE_GENERATION_CORRECTIONS.md).

SM_Reset is not a second SM_Init: it exits the current configuration (recording history), rebinds variables to their initial values, clears the machine arrays, and re-enters the default path; it then calls SM_WriteOutputs so that physical outputs match the post-reset state. There is no memset, because the instance is already a valid machine.

6.2 The tick contract

SM_Error_t SM_Step(ADIA_Instance_t *instance, uint32_t delta_ms)
{
    uint32_t state_index;
    if (instance == NULL) {
        return SM_ERR_NULL_INSTANCE;
    }
    if (instance->fault_latched || (instance->error_status != SM_ERR_NONE)) {
        SM_Enter_Fault(instance);
        return instance->error_status != SM_ERR_NONE ? instance->error_status : SM_ERR_SAFETY_VIOLATION;
    }
    if ((delta_ms < SM_TICK_MIN_MS) || (delta_ms > SM_TICK_MAX_MS)) {
        instance->error_status = SM_ERR_TIMING;
        SM_Enter_Fault(instance);
        return instance->error_status;
    }
    instance->error_status = SM_Validate_State_Consistency(instance);
    if (instance->error_status != SM_ERR_NONE) {
        SM_Enter_Fault(instance);
        return instance->error_status;
    }
    /* delta_ms is observed physical jitter; SM_TICK_MS is behavioral logical time. */
    for (state_index = 1U; state_index <= SM_NUM_STATES; ++state_index) {
        if (instance->state_active[state_index]) {
            if (SM_TICK_MS > (UINT32_MAX - instance->state_timers[state_index])) {
                instance->state_timers[state_index] = UINT32_MAX;
            } else {
                instance->state_timers[state_index] += SM_TICK_MS;
            }
        }
    }
    (void)SM_Execute_Layer_0(instance);
    if (instance->error_status != SM_ERR_NONE) {
        SM_Enter_Fault(instance);
    }
    return instance->error_status;
}

The order is the contract, and it is observable from outside:

  1. Fault short-circuit. A latched fault (or any recorded error) re-enters the fault path and returns; the machine never "runs on" after a safety event.
  2. Timing plausibility. delta_ms outside [SM_TICK_MIN_MS, SM_TICK_MAX_MS] is SM_ERR_TIMING → fault. Note the deliberate asymmetry: measured time is only validated, never accumulated — state_timers advances by the logical SM_TICK_MS, so jitter cannot change when a after() transition fires (this is why the harness can replay identical traces on a loaded host).
  3. Consistency check before acting — the machine refuses to execute on a corrupted configuration.
  4. Timers for every active state, saturating at UINT32_MAX instead of wrapping (an after guard on a long-lived state must not eventually fire early).
  5. Execution from the root layer down, then a second error check that latches faults raised by actions.
SM_Error_t SM_WriteOutputs(ADIA_Instance_t *instance)
{
    if (instance == NULL) {
        return SM_ERR_NULL_INSTANCE;
    }
    if (instance->fault_latched || (instance->error_status != SM_ERR_NONE)) {
        SM_Enter_Fault(instance);
        return instance->error_status != SM_ERR_NONE ? instance->error_status : SM_ERR_SAFETY_VIOLATION;
    }
    instance->error_status = SM_Validate_State_Consistency(instance);
    if (instance->error_status != SM_ERR_NONE) {
        SM_Enter_Fault(instance);
        return instance->error_status;
    }
    (void)instance;
    return SM_ERR_NONE;
}

SM_Sync_IO() is just ReadInputs() then WriteOutputs(); write-mapping conversion and safe-value substitution happen inside SM_ApplySafeOutputs. With no IO mappings — as in this model — SM_ReadInputs/SM_WriteOutputs degenerate to (void)instance;, and the consistency check remains. Notice it does not call SM_WriteOutputs' parent: re-entry is impossible.

6.3 How one transition becomes code

This is the single most characteristic piece of generated C. A cross-boundary transition (trip_overheat: heater → overheat, which exits an entire container tree) becomes:

static bool SM_Execute_State_1(ADIA_Instance_t *instance)
{
    bool transitioned = false;
    /* TRACE-BEGIN: traceId=TRACE-TRANS-TRIP_OVERHEAT symbol=sm_trans_trip_overheat */
    if (instance->data.over_temperature) {
        SM_Exit_State(instance, SM_ST_HEATER, true);
        instance->state_active[SM_ST_OVERHEAT_IDX] = true;
        instance->state_timers[SM_ST_OVERHEAT_IDX] = 0U;
        instance->active_states[0U] = SM_ST_OVERHEAT;
        SM_ST_OVERHEAT_Entry(instance);
        return true;
    }
    /* TRACE-END: traceId=TRACE-TRANS-TRIP_OVERHEAT */
    SM_ST_HEATER_During(instance);
    transitioned = SM_Execute_Layer_1(instance) || transitioned;
    if (!instance->state_active[SM_ST_HEATER_IDX]) {
        return transitioned;
    }
    return transitioned;
}

Read it as the four phases of Stateflow-compatible execution, all decided at generation time:

  1. Guard first, before any action. Transitions are evaluated in priority order; the first satisfied guard wins, and every other transition and the During action of this state are skipped for this tick (the early return true;).
  2. Exit — one call, SM_Exit_State(instance, SM_ST_HEATER, true). The true means "record history for the containing layer on the way out"; the function itself cascades into the child layers and exits warming → pwm_bank → pwm_high, fan_bank → fan_low in reverse containment order, zeroing timers and clearing slots.
  3. Entry — the emitted code writes the target's flags and the shared slot (active_states[0U] = SM_ST_OVERHEAT) and calls the user's entry action. Container entry is not a loop: it is the next function call.
  4. Report — return true tells the caller (and the generated test harness) that a transition fired this tick.
static bool SM_Execute_State_10(ADIA_Instance_t *instance)
{
    /* TRACE-BEGIN: traceId=TRACE-TRANS-RESUME_HEATER symbol=sm_trans_resume_heater */
    if (instance->data.stop_cmd) {
        SM_Exit_State(instance, SM_ST_OVERHEAT, true);
        instance->state_active[SM_ST_HEATER_IDX] = true;
        instance->state_timers[SM_ST_HEATER_IDX] = 0U;
        instance->active_states[0U] = SM_ST_HEATER;
        SM_ST_HEATER_Entry(instance);
        if (instance->deep_history[SM_LYR_HEATER_CHILDREN_IDX][SM_ST_STANDBY_IDX]) {
            SM_Restore_State_2(instance, SM_LYR_HEATER_CHILDREN_IDX);
        }         else if (instance->deep_history[SM_LYR_HEATER_CHILDREN_IDX][SM_ST_WARMING_IDX]) {
            SM_Restore_State_3(instance, SM_LYR_HEATER_CHILDREN_IDX);
        }
        else {
            SM_Enter_Layer_Default_1(instance);
        }
        return true;
    }
    /* TRACE-END: traceId=TRACE-TRANS-RESUME_HEATER */

}

The history-targeting transition has the same skeleton, but phase 3 ends in a restoration decision instead of a default entry: the generated code interrogates the deep-history bit matrix and calls SM_Restore_State_2/3 or falls through to SM_Enter_Layer_Default_1 (i.e. standby) when nothing was recorded. This is renderRestoreLayer() in smCGenerator.ts, and it is emitted only where a route's destinationKind is 'history' or where the destination owns a history junction.

6.4 Parallel (AND) decomposition

static void SM_Enter_Layer_Default_4(ADIA_Instance_t *instance)
{
    SM_Enter_Deep_4(instance);
    SM_Enter_Deep_7(instance);
}

Entering warming means entering both regions, in declaration order. The AND layer has no active slot, so "what is active inside warming?" is answered by state_active[SM_ST_PWM_BANK_IDX] and state_active[SM_ST_FAN_BANK_IDX] — and by the validation rule that requires every region of an active AND container to be active (§6.7).

static bool SM_Execute_Layer_4(ADIA_Instance_t *instance)
{
    bool transitioned = false;
    if (instance->state_active[SM_ST_PWM_BANK_IDX]) {
        transitioned = SM_Execute_State_4(instance) || transitioned;
        if (!instance->state_active[SM_ST_WARMING_IDX]) {
            return transitioned;
        }
    }
    if (instance->state_active[SM_ST_FAN_BANK_IDX]) {
        transitioned = SM_Execute_State_7(instance) || transitioned;
        if (!instance->state_active[SM_ST_WARMING_IDX]) {
            return transitioned;
        }
    }
    return transitioned;
}

Execution of an AND layer is a straight sequence of region executors, not a dispatch: every active region runs on every tick, in declaration order. After each region the generated code re-checks that the container is still active and returns immediately if it is not — that is how a transition taken in one region is allowed to leave the whole parallel state without the sibling region executing a state that no longer exists.

Execution order inside a state is fixed and identical for every state: own transitions → own During → child layer. Because a state function returns early once it transitions, a state that just left cannot run its During in the same tick; the if (!instance->state_active[…]) return transitioned; guard covers the case where a child transition exited an ancestor.

The timed transition pwm_step_up was declared with afterTicks: 20. The generator computes temporalThresholdMs = 200 and renders the guard against the per-state timer that the tick already maintains:

6.6 Deep history, end to end

History is the place where "state becomes C" is most visible, because the generator must decide what to store, when to store it, and how to reconstruct a nested configuration from booleans. Three mechanisms cooperate:

(a) Recording: a switch over layers, emitted once

static void SM_Record_Layer_History(ADIA_Instance_t *instance, uint32_t layer)
{
    uint32_t state_index;
    for (state_index = 0U; state_index <= SM_NUM_STATES; ++state_index) {
        instance->deep_history[layer][state_index] = false;
    }
    switch (layer) {
        case SM_LYR_ROOT_IDX:
            instance->history_states[0U] = instance->active_states[0U];
            instance->deep_history[SM_LYR_ROOT_IDX][SM_ST_HEATER_IDX] = instance->state_active[SM_ST_HEATER_IDX];
            instance->deep_history[SM_LYR_ROOT_IDX][SM_ST_STANDBY_IDX] = instance->state_active[SM_ST_STANDBY_IDX];
            instance->deep_history[SM_LYR_ROOT_IDX][SM_ST_WARMING_IDX] = instance->state_active[SM_ST_WARMING_IDX];
            instance->deep_history[SM_LYR_ROOT_IDX][SM_ST_PWM_BANK_IDX] = instance->state_active[SM_ST_PWM_BANK_IDX];
            instance->deep_history[SM_LYR_ROOT_IDX][SM_ST_PWM_LOW_IDX] = instance->state_active[SM_ST_PWM_LOW_IDX];
            instance->deep_history[SM_LYR_ROOT_IDX][SM_ST_PWM_HIGH_IDX] = instance->state_active[SM_ST_PWM_HIGH_IDX];
            instance->deep_history[SM_LYR_ROOT_IDX][SM_ST_FAN_BANK_IDX] = instance->state_active[SM_ST_FAN_BANK_IDX];
            instance->deep_history[SM_LYR_ROOT_IDX][SM_ST_FAN_LOW_IDX] = instance->state_active[SM_ST_FAN_LOW_IDX];
            instance->deep_history[SM_LYR_ROOT_IDX][SM_ST_FAN_HIGH_IDX] = instance->state_active[SM_ST_FAN_HIGH_IDX];
            instance->deep_history[SM_LYR_ROOT_IDX][SM_ST_OVERHEAT_IDX] = instance->state_active[SM_ST_OVERHEAT_IDX];
            break;

Shallow history is one word per layer; deep history is a bit per (layer, state) pair. Recording is triggered from the exit path, so it always happens before the flags are cleared — SM_Exit_State(state, /*record_containing_layer=*/true) uses a generated switch to map the exiting state to its containing layer. Note that SM_Record_Layer_History first clears the layer's row: a snapshot is a snapshot, never a merge with an older one.

(b) Restoring: recursion over the snapshot

static void SM_Restore_State_1(ADIA_Instance_t *instance, uint32_t snapshot_layer)
{
    (void)snapshot_layer;
    instance->state_active[SM_ST_HEATER_IDX] = true;
    instance->state_timers[SM_ST_HEATER_IDX] = 0U;
    instance->active_states[0U] = SM_ST_HEATER;
    SM_ST_HEATER_Entry(instance);
    if (instance->deep_history[snapshot_layer][SM_ST_STANDBY_IDX] || instance->deep_history[snapshot_layer][SM_ST_WARMING_IDX]) {
        if (instance->deep_history[snapshot_layer][SM_ST_STANDBY_IDX]) {
            SM_Restore_State_2(instance, snapshot_layer);
        }         else if (instance->deep_history[snapshot_layer][SM_ST_WARMING_IDX]) {
            SM_Restore_State_3(instance, snapshot_layer);
        }
    } else {
        SM_Enter_Layer_Default_1(instance);
    }
}

Each state has a restore function that (1) re-activates itself and re-runs its entry action, (2) asks its child layer's history which descendants were active, (3) recurses. A shallow junction would stop after step 1's layer choice; a deep junction keeps descending. The fallback branch (SM_Enter_Layer_Default_1) is what makes the first-ever entry well-defined: history arrays start cleared by SM_Init, so "no recorded child" is a normal case, not an error.

Safety is emitted as data plus one checker, and the checker's input is the machine's own RAM — which is exactly what gets corrupted in the field.

static bool SM_Is_Direct_Layer_Child
SM_Error_t SM_Validate_State_Consistency(const ADIA_Instance_t *instance)
{
    uint32_t layer_index;
    uint32_t state_index;
    uint32_t slot_index;
    SM_Node_t active_node;
    SM_Node_t history_node;
    int32_t active_slot;
    SM_Node_t parent;
    bool container_active;
    if (instance == NULL) {
        return SM_ERR_NULL_INSTANCE;
    }
    for (state_index = 1U; state_index <= SM_NUM_STATES; ++state_index) {
        if (instance->state_active[state_index]) {
            parent = SM_State_Parent_Map[state_index];
            if ((parent != SM_NODE_INVALID)
                && (!instance->state_active[(uint32_t)parent])) {
                return SM_ERR_CONFIGURATION;
            }
            active_slot = SM_State_Active_Slot_Map[state_index];
            if ((active_slot >= 0)
                && (instance->active_states[(uint32_t)active_slot]
                    != (SM_Node_t)state_index)) {
                return SM_ERR_CONFIGURATION;
            }
        }
    }
    for (layer_index = 0U; layer_index < SM_NUM_LAYERS; ++layer_index) {
        parent = SM_Layer_Parent_State_Map[layer_index];
        container_active = (parent == SM_NODE_INVALID)
            || instance->state_active[(uint32_t)parent];
        active_slot = SM_Layer_Active_Slot_Map[layer_index];
        if (container_active) {
            if (active_slot >= 0) {
                active_node = instance->active_states[(uint32_t)active_slot];
                if ((active_node == SM_NODE_INVALID)
                    || ((uint32_t)active_node > SM_NUM_STATES)
                    || (!SM_Is_Direct_Layer_Child(layer_index, active_node))
                    || (!instance->state_active[(uint32_t)active_node])) {
                    return SM_ERR_CONFIGURATION;
                }
            } else if (SM_Layer_Has_Children_Map[layer_index]) {
                for (state_index = 1U; state_index <= SM_NUM_STATES; ++state_index) {
                    if (SM_Is_Direct_Layer_Child(layer_index, (SM_Node_t)state_index)
                        && (!instance->state_active[state_index])) {
                        return SM_ERR_CONFIGURATION;
                    }
                }
            }
        } else if ((active_slot >= 0)

7Behaviour of the generation process (conformance gates)

Generating C is one thing; demonstrating that the generated C is the machine you specified is another. The pipeline is a strictly ordered set of 12 activities, and its status semantics are the interesting part:

Fail-closed ordering

structural → semantic → test-generation → host-compilation → host-runtime → sanitizers → coverage → differential → static-analysis → misra → target-compilation → hardware. A failure in host compilation marks all dependent activities NOT_RUN with the reason recorded — "we could not measure" is never reported as "we measured and it was fine".

Truthful statuses

PASS, FAIL, NOT_RUN (never attempted/unavailable), NOT_APPLICABLE (e.g. MC/DC for a non-safety model) and PENDING (hardware, always until a bench exists). deriveAcceptance() rejects on any FAIL and additionally requires nine gates to be PASS: structural, semantic, test-generation, host-compilation, host-runtime, sanitizers, statement-coverage, branch-coverage, differential. MC/DC and target compilation become mandatory only when the model's verification policy demands them; static analysis, MISRA and hardware do not block acceptance.

Cost model of one tick. O(active states) for the timer loop and the execution descent, plus O(outgoing transitions) for guard evaluation, with guards evaluated in priority order and evaluation stopped at the first satisfied guard. There are no writes to ROM, no allocations, and no unbounded loops: the deepest recursion is bounded by the model's nesting depth, which is a static property of the generated call graph.

10Deliberate non-goals

Not generated

  • No scheduler, RTOS binding or ISR — the integrator calls SM_Step(ms) at the tick rate and must act on the return code.
  • No MCAL implementation: mcal_dio.h is an interface only (6 functions).
  • No dynamic dispatch and no function pointers: dispatch is switch, so a corrupted instance can change which states run, but never which function is called.
  • No heap, no malloc, no recursion whose depth depends on data.
  • No events/queueing: the model is sampled, not event-driven; conditions are re-evaluated every tick.

Left to the integrator — and worth knowing

  • Clock accuracy: SM_TICK_MIN/MAX_MS is a plausibility window, not a scheduler. If the platform cannot hit the window, the machine faults by design.
  • Safe outputs: MCAL_ApplySafeOutputs() must actually de-energise the plant.
  • Watchdog: MCAL_Watchdog_Kick() is a hook; the policy (watchdogAfterCriticalFault: 'do-not-service') is a model setting, not generated logic.
  • Guards must be side-effect free. The pipeline's regression suite contains models that demonstrate why (smDifferential.test.ts covers action ordering across exit/during/entry phases — one action per tick is the contract).

Summary of the contract

A state machine's shape is compiled into constants and switches; its state is a caller-owned struct; its behaviour over time is a fixed sequence of phases per tick; its safety is a self-check against the same struct; and its equivalence to the specification is asserted by replaying one trace on two implementations (TypeScript interpreter and the compiled C) and comparing every frame. Where that chain currently has holes, they are enumerated in §8 — and every one of them makes the generator produce something, not become silent.
